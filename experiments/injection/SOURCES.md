# Probe provenance

The library/progress follow-up inspects official [melonDS 1.1](https://github.com/melonDS-emu/melonDS/releases/tag/1.1), its Qt/SDL input, portable config and MainWindow/EmuThread pause code, and its executable's arm64 symbols/instructions. The executable and symbol assets are pinned in `assets/setup/`; upstream GPLv3 source remains at that release. Broomm's bridge calls those measured symbols and rejects a different executable. It copies no emulator implementation and uses the child's existing SDL2 runtime. The static-build DynAPI check now uses three surviving exported stubs; required real getters are checked before sampling. `native/installer_guard.c` is original Broomm POSIX lock interop using the Apple SDK C runtime; Dart owns PS3 import workflows. Build recipes, source/output hashes, native checks and remaining acceptance are recorded in [the follow-up](../../docs/library-and-progress-followup.md) and its JSON.

The responsiveness follow-up inspects the pinned Azahar [startup/pause/close implementation](https://github.com/azahar-emu/azahar/blob/2126.1.2/src/citra_qt/citra_qt.cpp) and [loading-screen completion/fade](https://github.com/azahar-emu/azahar/blob/2126.1.2/src/citra_qt/loading_screen.cpp). The bridge guards the `OnLoadComplete` instructions before reading the loading widget at main-window offset `0x70`; `QWidget::isVisibleTo(parent)` distinguishes its own hidden state from a hidden/minimized parent. See [Qt visibility semantics](https://doc.qt.io/qt-6/qwidget.html#isVisibleTo). Qt documents that [quit before the main event loop starts has no effect](https://doc.qt.io/qt-6/qcoreapplication.html#quit); combined with Azahar's constructor warning/BootGame order and the failed native trace, this explains the early cancellation regression. No emulator/Qt implementation source is copied. New bridge hashes, measured samples and final regression results are in [pairing responsiveness evidence](../../docs/research/pairing-responsiveness.json); existing licenses/build recipes still apply.

The bridge and Dart tools here are new Broomm research code. No PGCS application code or Go code is imported. Installed emulator bundles and already supplied firmware/keys are copied **only into ignored private test directories**; they are not Broomm distribution assets. The probe loads each emulator's existing SDL runtime; it does not ship or load another SDL copy.

`src/abi_slots.h` contains selected macOS DynAPI slot metadata derived by `tools/derive-slots.dart` from these upstream ABI declarations:

The generated metadata is checked against **three actual dispatch stubs in every process** before deriving a table base. SDL2 and SDL3 use different calling conventions for several returns and callbacks; separate bridge variants preserve them. Append-only DynAPI declarations do not make arbitrary older/newer binaries supported. The runtime version, instruction pattern and tested build remain part of acceptance. See [SDL's DynAPI design](https://github.com/libsdl-org/SDL/blob/release-3.4.0/docs/README-dynapi.md).

The SDL declarations carry the zlib license, copyright (C) 1997–2025 Sam Lantinga. Preserve the original header notices when fetching them into `reference/`; the generated metadata is a Broomm derivation, not an unmodified SDL source file. SDL's [license](https://github.com/libsdl-org/SDL/blob/release-3.4.0/LICENSE.txt) allows modification and redistribution subject to retaining its notice and identifying altered source.
