# Intel RPCS3 on Apple Silicon

Implementation and native validation, 2026-10-22. This adds an alternate build of the existing concrete RPCS3 adapter, rather than a different save format or emulator engine. The [capture-library investigation](flutter-window-capture.md) is separate research; this change does not implement the loading preview.

## Selection and storage

Emulator Settings lists **RPCS3** and **RPCS3 Intel** under PlayStation 3. Each has its own setup/review, managed executable selection, remove action and **Set as default** button. A configured default is used by Home Play; removing it falls back to another configured PS3 choice. The preference is server-scoped and persists across restarts. The Intel card explains Rosetta is required on Apple Silicon. Broomm probes `/usr/bin/arch -x86_64 /usr/bin/true` with a ten-second bound before setup or launch and shows an actionable failure if unavailable. It never installs Rosetta, modifies global settings or updates an emulator automatically.

The distinct immutable release is `emulators/rpcs3-intel/<sha256>/RPCS3.app`. The ordinary profile remains `profiles/<profile-id>/emulators/rpcs3/`: both distributions consume the same Broomm-private `portable/` configuration, firmware, `dev_hdd0` games/licenses and savedata. This avoids a second empty local save becoming a cloud deletion when switching architectures. Existing profile ownership markers and the session/writer lease continue to protect it. Defaults do not modify savedata, and uninstalling either executable keeps this profile. Download Updates and DLC uses the selected configured variant; publication/removal remains owned by the existing PS3 add-on transaction.

Intel's private HOME is `home-intel/`, with a validated Broomm-created link to that same `portable/`; its macOS compilation cache is `home-intel/Library/Caches/rpcs3/cache/`, and its XDG/redirected cache is `cache-intel/`. Existing ARM HOME/cache directories are retained. System/default-user RPCS3 settings and caches remain outside the child's writable roots. Cloud sync continues using the same PS3 title-specific `rpcs3-savedata-v1` format and existing BROOMM history; PS3 save states remain unsupported.

The thin x86_64 executable hash is `6149f4458f3de4b087dc9aa7e8d0e951ce2ad64527d8ac545f30ff16a01f0a42`. No emulator source was patched or copied into Dart. Keep the upstream bundle's GPL/third-party notices when redistributing it; this development application ships metadata, not the emulator payload.

`tool/capture_rpcs3_intel_setup.dart <reviewed-RPCS3.app>` verifies that exact executable before generating file/link inventories, reviewed Qt symbols and the `Emu` state address. The default setup source is `prototype-data/rpcs3-intel/RPCS3.app`; sources and downloads stay ignored. For an independent local source, import the existing version-1 setup JSON schema with launcher key `rpcs3-intel`. Arbitrary versions remain rejected by the trusted inventory; a source path does not authorize new addresses or commands.

The three Broomm C libraries now contain arm64 and x86_64 slices. Dyld chooses the child architecture; the Flutter application's own architecture does not choose an incompatible thin library. The Intel SDL3 hook validates the inspected RIP-relative dispatch sequence; missing/different patterns fail closed. Native Qt symbols and the state object are tied to the Intel executable hash, independently of the ARM metadata. AppKit NSRect returns use `objc_msgSend_stret` on Intel and the previous return convention on ARM. The C bridge remains inside the emulator's own SDL runtime, holding its writer lock; no second input runtime or Go service is added.
