# Prototype reliability follow-up

Recorded 2026-10-16 on macOS 27.0.1, Apple M1 Pro/arm64, with the same prepared emulator builds and supplied ROMs as the [original prototype](prototype-validation.json). This follow-up distinguishes the owner's observations from automated native checks. Linux/Steam/gamescope and physical gameplay acceptance remain pending.

## Owner observations

The owner reported missing Broomm window decorations, frequent size changes (especially during initial pairing), one Broomm crash when closing Dolphin, RetroArch input working only on the first launch, and a Switch controller/pause acknowledgement failure. Dolphin also showed four connected players when only two controllers had been paired. These reports supersede any inference of acceptance from the original synthetic suite.

## Causes and changes

- **Window presentation:** every overlay presentation replaced the titled window style with a borderless style and assigned an emulator-derived or startup frame. Broomm now preserves its titled, resizable window and user-selected frame. Only level/Space behavior changes for the temporary desktop overlay. Emulator frame changes no longer resize Flutter.
- **Broomm crash:** the recorded crash was a native null dereference on `io.flutter.raster` in `impeller::Canvas::SetupRenderPass`, through `EmbedderExternalViewEmbedder::SubmitFlutterView`. This matches the reported [Flutter macOS backing-surface fault](https://github.com/flutter/flutter/pull/192522), including reports on 3.47.0. Broomm's macOS bundle opts into the pinned SDK's existing Skia Metal backend. Native execution confirms that backend loaded. This is a scoped workaround, not a Flutter engine patch or proof against every possible crash.
- **Return after emulator failure:** pending pause/resume continuations could outlive the emulator and overwrite the library state, reference cleared pairing state, or hide the returned window. Model lifetime checks invalidate that work. Normal and nonzero exits reset busy/presentation/input state and show the library. A failed pause rollback is caught separately; it cannot escape its error handler and strand the UI. IPC command publications are serialized, failures reach their caller, and recovery commands can still run.
- **RetroArch relaunch:** filtering SDL enumeration did not normalize SDL player indices. RetroArch's [SDL3 driver](https://github.com/libretro/RetroArch/blob/master/input/drivers_joypad/sdl3_joypad.c) can place a gamepad in its SDL-reported numbered slot, even when it is first in the filtered list. Physical pads present at SDL initialization change that numbering. The bridge now returns each logical route's own player index and publishes filtering before attaching the routes. The supervisor also resets native pause knowledge per launch and rejects old asynchronous replies across session lifetimes. Unknown is no longer represented as running.
- **Ryubing resume:** the configured F5 action was sent while Broomm owned foreground focus. Avalonia could ignore that hotkey. The injected path now activates the owning emulator, waits for its active state, sends its configured action, and still requires title/state readback. The delayed key release retains its window until delivery. The focus regression holds confirmation until the child's own AppKit state verifies that it lost focus to Broomm.
- **Ryubing relaunch stall:** a subsequent run exposed an additional deadlock with the two connected Switch Pro controllers. A native sample showed a GCController notification entering SDL 2.30's `IOS_AddJoystickDevice` → HID enumeration → nested CFRunLoop/Avalonia managed wait, while the bridge and input thread waited for SDL's joystick mutex. The per-child [SDL_JOYSTICK_MFI](https://wiki.libsdl.org/SDL2/SDL_HINT_JOYSTICK_MFI) setting disables that GCController backend for the pinned Ryubing build; HIDAPI/IOKit remain enabled. Both physical Switch Pro controllers remain discoverable. This is not a Linux default or a general recommendation to disable Apple controller support. MFi-only devices need separate verification with this workaround.
- **Ryubing window lifetime:** a later repetition lost its game window during the disconnect sequence while the emulator process remained alive. The subsequent shutdown crashed in Avalonia's `AvnWindow::performClose`/`objc_msgSend`. The bridge had captured a native window whose managed delegate could already be gone. Shutdown now resolves a current visible window at delivery time; queued key releases skip closed windows, and pause pulses wait for both key-window focus and the preceding release. A bounded content-title disappearance check requests normal shutdown if the game ends but the emulator remains open; hidden/minimized game windows are not evidence of absence. The original trigger for that intermediate game closure is not established by the crash report. A dedicated fixture closes the live game window normally and verifies an exit with status zero. Direct `NSApplication::terminate` was rejected after a native sample showed .NET waiting for surviving threads: that path bypassed Avalonia's window-lifetime teardown. Intentional bridge-worker shutdown no longer triggers the missing-snapshot watchdog.
- **Dolphin extra players:** all four `SIDevice` values were explicitly configured as GameCube pads. Neutral host input does not disconnect a console socket. Startup now leaves those sockets empty. The bridge updates Dolphin 2609's native current-run SI configuration from applied, present assignments, using its [configuration API](https://github.com/dolphin-emu/dolphin/blob/2609/Source/Core/Common/Config/Config.h). Dolphin's [SI update](https://github.com/dolphin-emu/dolphin/blob/2609/Source/Core/Core/HW/SI/SI.cpp) performs the live attach/detach. Native device types are inspected only with emulation confirmed paused; reconnection respects Dolphin's emulated unplug cooldown. Stable SDL routes remain available independently of connected console pads. Other emulators' console socket counts are not established by this Dolphin check.
- **Unresponsive bridge:** five seconds without a new sample after initial discovery invalidates pause knowledge and returns Broomm to pairing. Startup retains its separate 90-second discovery allowance. Broomm requests a gated pause for recovery, but does not claim it succeeded, force-terminate the emulator or release its writer lock. Logging failures remain independent of gameplay focus.

## Verification

The executable commands, inputs, portable results, build/source hashes and failed diagnostic run are recorded in [prototype regressions](prototype-regressions.json). Use the [README walkthrough](../../README.md) to repeat the owner checks. Tests use the real supplied ROMs and the emulator's own SDL runtime, with opt-in synthetic physical-source substitutes; these do not establish button handling on the owner's actual pads.

The expanded checks cover RetroArch's own numbered driver slots, multiple launches through one supervisor, controllers present before virtual routes, Dolphin's actual zero/one/two console socket counts, foreground loss before Switch resume, held-button gating, hotkey/disconnect pause, and ordinary native window decorations/frame preservation. The native window test repeatedly hides and shows a running Flutter view using the Skia Metal backend. These are native automated observations, not visual acceptance or evidence of a compositor overlay inside the emulator renderer.

One intermediate Switch relaunch stalled before its backend correction. Its stack sample is retained under ignored `.tool-cache/research/ryubing-stall.sample.txt`; the owned synthetic test child was terminated with SIGTERM after diagnosis. The later window-lifetime failure and the unsuccessful direct-quit experiment are retained as separate failed runs, not counted as successful acceptance. The direct-quit test child was also stopped with SIGTERM after sampling its completed-game teardown stall. No interactive session was force-stopped and no save directories were deleted. Restricted-sandbox test attempts could not bind Flutter/RetroArch loopback sockets or reach Xcode services/caches; authorized native execution was used without changing the tests or installing OS dependencies.

## Owner checks still needed

1. Resize Broomm, launch/pair, play, reopen pairing and close an emulator. Its normal title bar and chosen size should persist, and the library should return on exit.
2. Launch RetroArch several times with controllers already connected; verify actual in-game player input each time.
3. In Melee, pair two players and confirm exactly two connected ports; remove/rejoin a player during play and verify the port change after resuming.
4. In Switch, apply pairing from Broomm, use R3+Select to reopen it, and resume repeatedly with actual controllers. Verify assignment and mappings, not just pause acknowledgements.

Do not infer Steam/gamescope, fullscreen Space, Windows, Android, rumble/motion or every pad model support from these macOS checks. The separate-window presentation remains provisional for the [Steam launch flow](controllers-and-overlays.md#steam-big-picture-and-gamescope-preliminary-window-review).
